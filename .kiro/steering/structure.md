# EventHub Project Structure

## Repository Structure

The project is organized into separate frontend and backend areas.

    event-registration-portal/
    ├── .kiro/
    │   ├── hooks/
    │   ├── specs/
    │   ├── steering/
    │   └── ugmdu.json
    ├── backend/
    │   └── functions/
    │       ├── registerStudent/
    │       ├── listRegistrations/
    │       ├── checkInRegistration/
    │       └── updateRegistration/
    ├── frontend/
    │   ├── src/
    │   ├── public/
    │   ├── dist/
    │   ├── package.json
    │   └── vite.config.js
    └── README.md

## Kiro Directory

The .kiro directory contains Kiro-related project configuration and development guidance.

### steering/

Contains persistent project context used to guide development.

- product.md - Product purpose, users, features, and product principles.
- tech.md - Technology stack, AWS services, architecture, and technical principles.
- structure.md - Repository structure and organization conventions.

### specs/

Contains the specification for the EventHub project.

The specification includes:

- requirements.md
- design.md
- tasks.md
- .config.kiro

### hooks/

Contains Kiro hook configuration used by the project.

## Backend Structure

Backend Lambda functions are stored under:

    backend/functions/

Each Lambda function has its own directory and implementation.

### registerStudent/

Responsible for:

- Validating registration data
- Checking duplicate registrations
- Generating registration IDs
- Storing registrations in DynamoDB
- Publishing registration notifications

### listRegistrations/

Responsible for:

- Reading registration records from DynamoDB
- Returning registration data to the admin dashboard
- Providing check-in information

### checkInRegistration/

Responsible for:

- Receiving a registration ID
- Finding the registration in DynamoDB
- Preventing duplicate check-in
- Updating check-in status
- Recording check-in time

### updateRegistration/

This function exists in the repository for historical/specification purposes but is not part of the current deployed application and must not be used or deployed.

## Frontend Structure

The frontend is located under:

    frontend/

Important source files include:

- App.jsx - Main student-facing application and registration flow.
- AdminLogin.jsx - Administrator login interface.
- AdminDashboard.jsx - Registration management and QR check-in dashboard.
- App.css - Main application styling.
- index.css - Global styling.
- main.jsx - React application entry point.
- amplifyConfig.js - AWS-related frontend configuration.

## Frontend Assets

Static frontend assets are stored under:

    frontend/src/assets/

Production build output is generated under:

    frontend/dist/

The dist directory contains the files generated by Vite for production hosting.

## Development Conventions

- Keep frontend code inside frontend/.
- Keep backend Lambda functions inside backend/functions/.
- Keep Kiro project guidance inside .kiro/.
- Keep each Lambda operation isolated in its own directory.
- Avoid modifying unrelated project files.
- Do not deploy unused Lambda functions.
- Preserve existing working functionality when making changes.
- Keep backup files out of the production source structure.

## Change Management

Before making significant changes:

1. Understand the existing implementation.
2. Identify the affected frontend or backend component.
3. Make the smallest practical change.
4. Test the affected functionality.
5. Run the production build when frontend code changes.
6. Verify the result before committing changes.

## Source Control

Git is used for version control.

Changes should be reviewed before staging and committing.

Only intentional project files should be committed. Local backup files and temporary files should not be committed.
